# ForegramPM — catalogue de messages, français (fr)
#
# Une entrée par ligne : `clé = modèle`, comme dans en.txt, dont ce fichier
# reprend les clés du produit (le banc, ses familles bench et board et ses
# refus GML, ELK, MCD et REF, ne parle qu'anglais) avec les mêmes emplacements.
# Typographie : guillemets « » autour des noms, accents graves autour des
# clés du format, espace insécable (U+00A0) avant : ; ! ? et dans les « ».
# Un repère de fichier ou de position (« g.json:1:1: ») garde la forme
# anglaise, que les éditeurs savent lire.
# Pluriel : la variante `.one` sert pour 0 et 1, `.other` au-delà.

# Syntaxe JSON
JSN001.utf8 = octets invalides : le texte doit être en UTF-8
JSN001.bom = indicateur d'ordre des octets (BOM) refusé au début du texte
JSN002.value-char = caractère inattendu `{char}` : on attend une valeur
JSN002.value-word = mot inconnu `{word}` : on attend une valeur
JSN002.expected = caractère inattendu `{char}` : on attend {expected}
JSN003.value = fin de texte inattendue : on attend une valeur
JSN003.expected = fin de texte inattendue : on attend {expected}
JSN003.string = chaîne non terminée
JSN004 = nombre non entier : seuls les entiers sont admis
JSN005.digit = nombre mal formé : un chiffre est attendu après `-`
JSN005.zero = nombre mal formé : zéro en tête
JSN005.minus-zero = nombre mal formé : `-0` s'écrit `0`
JSN006 = entier trop grand pour être représenté
JSN007.control = caractère de contrôle {char} non échappé dans une chaîne
JSN007.high = surrogate haut sans son surrogate bas
JSN007.low = surrogate bas isolé
JSN007.escape = séquence d'échappement inconnue
JSN007.hex = quatre chiffres hexadécimaux sont attendus après `\u`
JSN008 = clé `{key}` en double dans le même objet
JSN009 = imbrication trop profonde : {max} niveaux au plus
JSN010 = contenu inattendu après la valeur : `{char}`

# Ce qu'attendait le lecteur JSON
expect.comma-bracket = `,` ou `]`
expect.comma-brace = `,` ou `}`
expect.colon = `:`
expect.key = une clé entre guillemets

# Structure, pour les deux formats
SCH001 = {field} : type {expected} attendu, type {found} reçu
SCH001.point = {field} : un point s'écrit [x, y], deux entiers
SCH001.segment = {field} : un élément de tracé est un point [x, y] ou une courbe [[x, y], [x, y], [x, y]]
SCH002 = clé inconnue `{key}` ({in})
SCH003 = clé obligatoire `{key}` absente ({in})
SCH004 = format inattendu `{found}` : on attend `{expected}`
SCH005 = version {found} non prise en charge : les versions 1 à {supported} sont lues
SCH006 = {field} : valeur inconnue `{value}` ; on attend l'une de {words}
SCH007.empty = {field} : identifiant vide
SCH007.control = {field} : l'identifiant contient un caractère de contrôle
SCH007.long = {field} : identifiant trop long ({length} caractères, {max} au plus)
SCH008 = {field} : {value} hors de l'intervalle de {min} à {max}

# Lecteur du format source (.fg)
SRC001 = octets invalides : le texte doit être en UTF-8
SRC002 = caractère de contrôle {char} refusé : seuls la tabulation et les fins de ligne sont admis
SRC003 = chaîne non fermée avant la fin de sa ligne
SRC004 = échappement inconnu `{escape}`
SRC005 = l'échappement `{escape}` n'est pas une valeur scalaire Unicode
SRC006 = `}` sans bloc ouvert
SRC007 = bloc non fermé avant la fin du fichier
SRC008.top = hors de tout élément, une ligne est une tête d'élément ou, avant le premier élément, une directive
SRC008.kind = une tête d'élément commence par un mot de sorte, qui ne commence pas par `@`
SRC008.id = une tête d'élément donne un identifiant après sa sorte, sous forme de mot
SRC008.label = seule une étiquette, entre guillemets, peut se placer entre l'identifiant et `{`
SRC009 = identifiant `{id}` : lettres ASCII, chiffres et `_` seulement, sans chiffre en tête
SRC010 = directive `@{key}` après le premier élément : l'en-tête précède tous les éléments
SRC011 = `@` sans clé
SRC012 = identifiant `{id}` déjà défini en {line}:{col}
SRC013 = clé `@{key}` déjà donnée en {line}:{col}
SRC014 = plus de {max} blocs imbriqués
SRC015 = référence `{id}` : aucun élément ne porte cet identifiant

# La ligne de commande du produit, `foregram`
cli.usage = usage : foregram [--lang <code>] [--json] <commande> ...\n       foregram validate <graphe.json> [<placement.json>...]\n       foregram check <fichier.fg>...\n       foregram canon <fichier.json|fichier.fg>\n       foregram metrics <graphe.json> <placement.json>...\n       foregram render <graphe.json> <placement.json> <sortie.svg|sortie.png> [--scale <n>]\n       foregram --help | --version\n\n  validate  Valide un graphe, puis chaque placement par rapport à ce graphe.\n  check     Vérifie que chaque fichier source est bien formé : sa grammaire\n            et ses identifiants ; ce que dit son contenu revient à la notation.\n  canon     Lit un graphe ou un placement, reconnu à sa clé `format`, ou un\n            fichier source, et l'écrit sous sa forme canonique sur la sortie.\n  metrics   Confronte chaque placement au graphe et écrit ses mesures, une\n            ligne par mesure.\n  render    Confronte le placement au graphe et le dessine, d'aspect neutre,\n            dans un fichier SVG ou PNG choisi par son extension ; --scale\n            donne au PNG ses pixels par pixel du dessin, de 1 à 8.\n\n  Un fichier nommé - est l'entrée standard, une fois par appel.\n  --lang    Langue des messages : `en` (par défaut) ou `fr`.\n  --json    Résultats et refus en JSON, un objet par ligne, tous sur la\n            sortie standard ; voir docs/exchange-format.md.\n\ncodes de sortie : 0 tout est valide, 1 un fichier est refusé, 2 appel\n                 incorrect ou fichier illisible
