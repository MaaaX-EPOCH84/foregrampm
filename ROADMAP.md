## Stage 1 — Corpus and exchange format  [E1]
1.1 ✅ [P1] Benchmark exchange format: abstract graph as JSON (nodes and their sizes, edges, optional attach sides and constraints), documented schema, validator that refuses with a precise message. Sets up the Rust workspace. — Done 2026-10-06. Two files, `foregram-graph` and `foregram-layout`, the layout repeating nothing of the graph so an engine can only omit or invent, never alter. Integers only, in hundredths of a pixel (rejected: whole pixels, too coarse for text metrics and centring; 1/64, less readable), y pointing down. Flat graphs, rectangular nodes, polyline routes, loops and parallel edges allowed, edge labels with an anchor (Merise cardinalities). Constraints: `direction`, `layer`, `order`, attach sides; no pinned position in version 1. The validator checks imposed sides but not `layer`/`order`, which are benchmark measurements. Hand-written strict JSON reader with line and column on every value (rejected: serde, which gives no position for meaning errors and accepts floats). Stable error codes (J, S, G, L), messages and documentation in English, keys in English. Attested by 49 tests including three guards (documentation shows the example files byte for byte, lists exactly the codes the code produces, every code is exercised), each guard checked by mutation; Clippy and rustfmt clean; command tried on empty, directory, random bytes, and a 200,000-node graph (2 s); identical output over two runs. Not verified: WebAssembly build (target not installed); memory use is 13× the input size.
1.2 ✅ [P10] Localisable messages: a diagnostic carries its code, its position and its arguments; the sentence is composed at display time from a per-language catalogue, English as the only language for now; every message of P1 converted; a test guarantees that every code has a catalogue entry. Same design as GIMO's, so the two tools can share catalogues one day. — Done 2026-10-09. No sentence left in the code: a refusal or a command output carries a key and arguments, an argument being either verbatim text or a nested message translated in turn. One catalogue for the whole product, library and benchmark command line, `crates/foregram-graph/messages/en.txt`, one `key = template` per line, `{name}` for an argument, `\n` for a line break. A refusal key is its stable code plus a variant when needed (`J005.zero`); other keys are fragments (`subject.node`). A missing key renders raw instead of failing. Rejected: a Rust type per message (the compiler would check arguments, but the catalogue would no longer be a file a translator can write alone; tests do that check instead); one catalogue per crate. Syntax chosen here, to be confronted with GIMO's agent when GIMO implements its own decision of 2026-10-06. English output unchanged byte for byte, except `0 nodes` instead of `0 node` (English plural rule). Attested by 59 tests, three of them guards (every refusal agrees with its template, also as a debug assertion at creation; every catalogue entry is reached and none is dead; every key written in the code exists), each guard checked by mutation; a French test catalogue shows a language switch. Limits: reading a catalogue stays internal until its own refusals get codes; plural follows the English rule only.
1.3 ✅ [P11] Exchange format v2: ports (optional side, position and size; order fixed per node with `ports_ordered`; shared attach point), nested nodes with `padding` and relative positions, routes as straight and cubic Bézier segments; validator, canonical form and documentation updated. — Done 2026-10-10. Node and port identifiers unique in the whole graph (rejected: per-node port names as in ELK; the import prefixes the 44 elk-models files that repeat one). Ports: `side`, `x`/`y` and `width`/`height` per port, `ports_ordered` per node meaning the list order; a port position requires a side and lies on it; a container cannot position its ports (rejected: one constraint level per node as in ELK, which cannot pin a single port; a `rank` per port, redundant with the list order). An edge end has a port or a side, never both (rejected: ports everywhere, too verbose for small diagrams). A container has no size in the graph and gets it from the layout, with an optional `padding` (rejected: a size in the graph, which would be either a wish or an unsatisfiable constraint). Node positions relative to the parent, port anchors relative to the node, routes and edge labels absolute (rejected: everything relative, which would give routes a container they do not have). Routes as a list of segments, a point or a cubic triple, so version 1 routes stay valid (rejected: two exclusive keys; polylines only with rounded corners, which would misrepresent Graphviz and ELK). The port box is centred on its anchor and a route may end anywhere in it. Versions 1 and 2 are read, 2 is written. Not checked by the validator: `layer`, `order`, port order (benchmark measurements). Attested by 78 tests, 29 new, three catalogue guards kept, four mutations detected (padding ignored, port box ignored, sized container accepted, relative positions read as absolute); the `components` example (container, pinned port with a box, edge to own container, curve) is valid and canonical; version 1 files read and come back as version 2; 46 MB graph in 2.6 s; nesting read up to 31 levels; identical output over two runs. Limits documented: rectangular nodes, no node labels, one direction, no hyperedges, about thirty nesting levels.
1.4 ✅ [P2] Public corpus: download and licences: manifest (address, version, SHA-256), replayable script that downloads Rome, North and elk-models into an ignored cache and checks them; licences read and recorded, nothing versioned. — Done 2026-10-10. `corpus/manifest.txt` gives per corpus the address, version date, SHA-256 (archives) or full commit (git), file pattern and exact count, and the licence with where it was read; `corpus/fetch.sh` downloads into `corpus/cache/` (ignored, 148 MB) and brings the cache back to the manifest on every run: an archive already matching is not downloaded again but always re-extracted, local changes to the git checkout are discarded and reported. Exit codes 0 matching, 1 mismatch, 2 call, tool or network. Rejected: a Rust `fetch` command (not product code; HTTP, TLS and tar would add about fifteen dependencies); GitHub's `archive/<sha>.tar.gz` for elk-models (its bytes are not guaranteed stable), replaced by a depth-1 `git fetch` of the commit; a cache outside the repository (a fresh clone stays self-contained). Licences: Rome and North display none on graphdrawing.unipg.it nor in the archives; elk-models is EPL-2.0 except `realworld/ptolemy/` (550 files), under the BSD-style Ptolemy II licence of the University of California. Attested: first run 3.9 s, 11,534 + 1,277 `.graphml` and 898 `.elkt`; second run downloads nothing; wrong SHA-256, wrong count and missing key refused; corrupted archive, deleted file and edited checkout repaired; nonexistent commit fails with code 2 (indistinguishable from a network failure); `git status` clean after runs; Clippy, rustfmt and 78 tests unchanged. Not checked: shellcheck (not installed). The archives' `Graph.log` give node and edge counts per graph, to check the P12 import.
1.5 ✅ [P12] GraphML import (Rome, North) with `roxmltree`: every node gets the same fixed size, recorded in the manifest; Rome edges oriented in file order; every converted graph validates. — Done 2026-10-10. `crates/foregram-bench/src/graphml.rs`, `roxmltree` 0.21.1 being the benchmark's first dependency (read-only tree with element positions, MIT or Apache-2.0, `memchr` only); `foregram-graph` stays dependency-free. Every node is 4950 × 3500, the exact A4 proportion 99/70 in landscape, A4 divided by 6 and the closest to Graphviz's default 54 × 36 (rejected: 29.7 × 21, 59.4 × 42, 99 × 70); the size is recorded as `node_size` in `corpus/manifest.txt` and a test ties it to the code. Graph named after the file, GraphML identifiers kept, edges from `source` to `target` as written, no `direction` (North has no `edgedefault`, so directed; Rome is undirected). Conversion in memory, nothing written to the cache; `graphml <file>` writes one converted graph for inspection (rejected: JSON copies in the cache). Only what the exchange format can say is accepted: `key`, `data`, `port`, hyperedges, nested graphs and unknown attributes are refused, not dropped; `xsi` attributes, comments and processing instructions are ignored; the DTD is allowed and never fetched. Refusals form the `X` family (X001 to X008: not UTF-8, malformed XML, wrong root, not exactly one graph, unsupported element or text, unsupported attribute, missing attribute, invalid `edgedefault`/`directed`), positioned in the `.graphml` in code points; validator refusals point there too. Checked against `Graph.log` by a benchmark command, `check-corpus <cache>` (rejected: a test that passes silently without the cache). Attested: `check-corpus corpus/cache` converts 11,534 Rome graphs (603,691 nodes, 796,512 edges) and 1,277 North graphs (41,032 nodes, 57,578 edges), all valid and matching `Graph.log`, in 2 s in release; all 12,811 converted graphs pass `validate`, are identical over two runs and keep the file's edge order; 97 tests, 19 new, every `X` code exercised and documented by the existing guards; six mutations detected (dropped edge, ignored `data`, edge count not compared, size changed in code only, catalogue entry removed, code without test); Clippy and rustfmt clean; `corpus/fetch.sh` still accepts the manifest and passes shellcheck 0.9.0. Limits: the X002 detail is roxmltree's English sentence, repeating the position; an `edge` without `id`, legal in GraphML, is refused (X007), Rome and North always having one.
1.6 ✅ [P13] ELKT reader and import: reader written from the official `ElkGraph.xtext` grammar, with error positions; all 898 elk-models files read; properties kept as typed key-value pairs; ports, nesting and sizes carried into format v2. — Done 2026-10-10. Reader `crates/foregram-bench/src/elkt.rs`, written from `ElkGraph.xtext` at commit `60b6846` of `eclipse-elk/elk` (EPL-2.0 or GPL-3.0-or-later; the grammar is cited, not copied), with the Xtext scoping, `ElkUtil.calcPortSide` and `PortListSorter` read in the source to reproduce ELK's choices: hand-written lexer and recursive descent, keywords reserved unless escaped with `^` (the corpus writes `^port.side`), unordered `layout` groups refusing a repeated key, property keys without blanks, Java escapes decoded in strings, numbers kept as written, every element positioned; the tree keeps everything, properties included, as typed values. Import `src/elk.rs`: nesting, sizes in hundredths rounded to the nearest, ports with box, side, order and anchor read as ELK does under `portConstraints` (`FREE` carries nothing, `FIXED_SIDE` the side or the one inferred from the position, `FIXED_ORDER` ELK's order by side then `port.index` or position, `FIXED_POS` the box centre brought onto the border, a missing position meaning (0, 0)), root `direction`, edge labels with a size and their `edgeLabels.placement`. Identifiers kept as written when distinct in the whole graph, else the path for nodes, `node.port` for ports, `container.id` for edges; an edge without one gets the first free `e<n>` in file order; references resolved like Xtext's scope: container, ancestors, root, absolute. Decided: a leaf without a size, which ELK takes as 0 × 0, gets 1 × 1, the smallest size of the format, counted (rejected: refusing, which lost 231 of 898 files; a default size as for Rome, which would skew the comparison with ELK); a container's pinned port positions are dropped and counted; `FIXED_RATIO` refused. Not carried and counted: node and port labels, edge labels without a size; layout options, positions and sections are results, not carried. `elkt <file>` writes one converted graph; `check-corpus` covers elk-models against `corpus/manifest.txt` (`count`, `imported`), read next to the cache. Refusals E001 to E006 (reader) and E007 to E011 (import), positioned in the `.elkt`. Attested: 898 files read and imported, all valid, 21,974 nodes, 50,099 ports, 28,861 edges, in 2.5 s with Rome and North in release; same digest of the 898 outputs over two runs; every output passes `validate`; 123 tests, 26 new; nine mutations detected (catalogue entry removed, documentation row removed, `FIXED_SIDE` ignored, rounding changed, edge order lost, duplicate layout key accepted, absolute names not resolved, container positions not counted, `FIXED_ORDER` not carried); Clippy and rustfmt clean. Not carried, 21,733 labels, 906 sizeless leaves, 4 pinned ports on containers. Limits: `nodeSize.constraints` and `nodeSize.minimum` (21 files) are not interpreted — ELK computes those sizes, to be taken from ELK's output in P4; the catalogue key guard now only takes a dotted literal for a key when its family exists in the catalogue, ELK option identifiers being dotted too.
1.7 ✅ [P3] In-house corpus: real CDMs converted with their links, plus two hard cases (central entity with eight associations, reflexive association); one set stays local, outside the repository. — Done 2026-10-10. Models written in the text format of the first prototype, `.mcd` (entities, properties, identifiers, associations, cardinalities), converted in memory by `foregram-bench mcd <file>`, `crates/foregram-bench/src/mcd.rs` (rejected: v2 JSON written directly, which loses the properties that give a node its size). Same refusals as the prototype, positioned, family `M` (M001 to M008: not UTF-8, line in column one that starts no block, indented line before any block, link inside an entity, line neither a property nor a link, block declared twice, link to what is not a declared entity, association with fewer than two links). One node per entity and per association in file order, one edge from the entity to the association per link, named `ASSOCIATION.ENTITY` and `.2` for the second end of a reflexive association, the cardinality as a label at the source, direction `right` as in the prototype. Sizes by a provisional rule, 7 px per character, 18 px per line, 8 px margin, labels 7 px per character plus 2 on each side, to be replaced by the embedded font metrics in P6 (rejected: reading Lato now; a fixed size as for Rome, which would give a fifteen-property entity the shape of an empty one). Tracked corpus `corpus/mcd/`: `gestpret` (the prototype's own example), `interpreteur_wl` (11 entities from its WinDev analysis, 4 associations with the cardinalities measured by `HListeLiaison`, since `.xdd` files carry no link), `commande` (an entity in eight associations), `employe` (two reflexive associations, one with properties). Local set in `corpus/local/`, ignored by Git: a WinDev analysis converted by a throwaway script outside the repository, links inferred from key names with default cardinalities 1,1 and 0,n, two ambiguous keys left unlinked and noted in the file (rejected: decoding the binary `.wdd`, undocumented). Attested: the four tracked models convert to valid graphs whose node and edge counts match counts made by hand in the sources (19/18, 6/8, 3/2, 15/8), a test holding both the list of files and the counts; every model also passes the prototype; the local set converts to a valid graph of 51 nodes and 46 edges; same bytes over two runs; 138 tests, 15 new; nine mutations detected (label anchored at the association, edge reversed, reflexive suffix lost, `#` counted in the width, one-link association accepted, entity and association sharing a name, catalogue entry removed, documentation row removed, direction lost); the three catalogue and documentation guards extended to the `M` family; Clippy and rustfmt clean. Limits: the local set's inferred links and cardinalities have not been reviewed by hand yet; no roles on links, so the two ends of a reflexive association are told apart only by their order; sizes are approximate until text is measured.

## Stage 2 — Measurement  [E14]
2.1 ✅ [P4] References: ELK and a recent Graphviz, at pinned versions, returning coordinates in a common JSON; failures are listed, not hidden. — Done 2026-10-11. The common JSON is the layout format itself. `foregram-bench layout <dot|elk> <cache> <graph>` lays out one graph, `layout-corpus <dot|elk> <cache> <out>` every graph of the corpora, writing the layouts under `<out>/<engine>/` and every failure, with its code, in `failures.txt`; refusal family `R` (R001-R007), documented in `docs/exchange-format.md`, section "Reference engines". Engines pinned in `corpus/manifest.txt` and installed by `corpus/fetch.sh` without touching the machine: Graphviz 16.1.0 from the Ubuntu 24.04 `.deb` of the release, unpacked with `dpkg -x` (plugins with a missing library dropped, `dot -c`); ELK 0.12.0 as twelve jars from Maven Central, each with its SHA-256, and the benchmark's Java driver `crates/foregram-bench/java/ElkDriver.java` compiled against them (a JDK is needed; `openjdk-21-jdk-headless` installed for it). The benchmark refuses an engine whose version differs from the manifest. Decided: ELK driven through its Java API by a line protocol on stdin/stdout, one JVM per run, 60 s per graph (rejected: ELK JSON, which needs a float reader; a JVM per graph; `elkrs`, a one-person Rust port of doubtful licence; elkjs under Node, a transpilation); `dot` read through `-Tjson0`, strings only, with the format's own strict reader (rejected: `-Tplain`, lossy; `-Tdot`, a DOT parser); nodes named `n<rank>`, so no identifier escaping. Lowering: sides to compass points and `FIXED_SIDE` ports; edges to a container through its first leaf and `lhead`/`ltail`; labels as fixed-size HTML tables for dot, text-bearing labels for ELK; `portConstraints` from the most demanding port; `portBorderOffset = -size/2` so ELK centres a port box on the border (verified in ELK's `LGraphUtil.initializePort`: by default the box sits outside, and the anchor is the outer edge); `hierarchyHandling=INCLUDE_CHILDREN` for nested graphs; layers and orders passed to neither. Verified on a real case: ELK edge and label coordinates are relative to the edge's containing node; the driver returns absolutes, rounded once. A route end within 1.5 px of its target is brought onto it and counted (dot clips curves 0.55 pt short at most and attaches a compass point exactly 1 pt outside the node). Measured: ELK lays out Rome 11534/11534, North 1277/1277, mcd 4/4, elk-models 878/898 in 1 min 30 (19 Ptolemy leaves too small for their ports, one ELK exception); dot lays out Rome, North and mcd entirely, elk-models 431/898 in 6 min (no ports, 1 × 1 leaves enlarged, 26 `triangulation failed`). Those 19 graphs will leave the bar in P9; the right fix is automatic node sizing, ports included, in the compiler.
2.2 ✅ [P5] Metrics: crossings, bends, edge length, overlaps, area and proportions, written as product code, with a textual report of the layout; tests on cases with known values. — Done 2026-10-11. `Metrics::measure(graph, layout)` in `crates/foregram-graph/src/metrics.rs`, integers only, on a layout that passes the check; `report()` gives one catalogue line per measure; `foregram-bench metrics <graph> <layout>...` prints them and refuses a layout that fails the check; section "Metrics" of `docs/exchange-format.md` defines every measure. Decided: every curve is flattened into 16 straight segments, rounded to the nearest hundredth, and every measure reads the polyline (rejected: the control polygon, which miscounts crossings; adaptive steps, which vary with size); a bend is a vertex between two straight segments where the direction changes, exact integer collinearity, no threshold, a curve and its junction with a straight segment never bending (rejected: the total angle turned); crossings are pairs of segments of distinct edges meeting in a point interior to both, a pass through a vertex of the other route judged by the side of its two neighbours, a common end never counted; collinear overlapping stretches are counted apart, with their length added up, so the renderer can thicken a shared stretch; node overlaps by pair with their area, ancestor and descendant excluded, touching not overlapping; edges through a foreign node by pair, the ends and their ancestors exempt; label overlaps with any node but a container of the edge, any other label, any other edge; extent as the bounding box of nodes, route points and labels, proportion and density in thousandths; broken constraints by pair for `layer` along `direction` (`right` by default), `order` across it, and port order read clockwise under `ports_ordered`, an equal position being a violation (rejected: deferring constraints to P9). No JSON yet: P7 will add it on the same struct with its need. Attested: 17 tests on hand-counted cases (X, L, U, reversal, curve chord, vertex pass and touch, roof and wedge, shared stretch, end to end, node pairs and containers, edge along a border, labels on node, edge and label, extent with a protruding route, layers in `right` and `down`, ports on north, west and south), the `components` example checked by hand (2 bends, longest 8000, density 358); 176 tests, eleven mutations detected (bends on curves, touch counted, label in own container, parent-child pair, south side read forwards, node touch, end-to-end shared, truncated thousandths, equal layer position, catalogue entry removed, documentation step count changed); Clippy and rustfmt clean; 300 North graphs measured twice with identical output, dot 17,125 crossings and 0 bends, ELK 15,677 crossings and 22,348 bends, neither through a foreign node; 0.13 s on the largest ELK layout. Limits: length is the sum of per-segment rounded roots; a route crossing another exactly at a reversal point is judged as a straight pass; no per-element detail in the report, only totals.
2.3 ✅ [P6] Neutral rendering: SVG and PNG drawn from the coordinates alone, same look for every engine, to compare the layout and not the style. — Done 2026-10-11. A new product crate, `foregram-render`, depending on `foregram-graph` only: a `Scene` of classed rectangles, routes and polygons built once from the layout, which the SVG and the PNG both draw, so the two show the same thing (rejected: rendering in the benchmark, which is not product code; in `foregram-graph`, which the PNG would give a dependency). Neutral look in one `Style`: light grey leaves with a 1 px dark border, containers as a thin lighter border, edges as 1 px lines with a triangle at the end, labels as dashed empty rectangles, ports as 4 px squares or their own box; monochrome, two widths. No text, since the format carries none: identifiers go into SVG `<title>` elements; Lato — metrics, embedded subset, glyphs — moves to the compiler, where text enters, and the `.mcd` sizes keep P3's provisional rule until then (rejected: a font just to draw identifiers; metrics alone for `mcd.rs`, which would fix font size and margins before the compiler exists). The view is the metrics' extent plus a 10 px margin, automatic only; fixed proportions and sizes come with the source format. SVG built by hand: pixel coordinates from the hundredths by integer arithmetic, one `<style>` block with classes so the board can restyle, nothing from the machine or the date. PNG rasterised here in integers — every element a polygon, non-zero winding, 16 sub-scanlines per row with exact horizontal coverage in 256ths of a pixel, one 8-bit grey channel — and encoded by the `png` crate 0.18.1 (MIT or Apache-2.0, eight crates beneath, all MIT or Apache) behind a Cargo feature, so the crate has no dependency for the SVG (rejected: a hand-written deflate, a reinvention without a reason; `resvg`/`tiny-skia`, about thirty crates with SIMD paths of unverified identity across machines and system fonts to silence). Curves drawn as curves in the SVG and as the metrics' 16-step polyline in the PNG, the image showing what was measured. Command `foregram-bench render <graph> <layout> <out.svg|out.png> [--scale n]`, scale 1 to 8, images over 50,000,000 pixels refused; family `V` (V001 to V003), documented in section "Neutral rendering". `foregram-graph` now exposes `Layout::absolute_rects`, `polyline` and `extent`. Attested: the two example SVGs frozen byte for byte as golden files; the `components` SVG rendered by Inkscape is identical to the PNG rendered here; a North graph laid out by dot and by ELK read back as images, faithful to the metrics; the largest ELK layout, 13,066 × 2,991 px, rendered in 1.9 s with the same SHA-256 over two runs, SVG likewise; 192 tests, 16 new (golden SVGs, drawing order, view with a protruding route and label, PNG decoded and sampled, empty layout, bounds; rasteriser on a pixel-aligned rectangle, half-pixel edges, a diagonal's symmetry, a ring's hole, overlapping strokes, dashes, the encoder on a short buffer); eleven mutations detected (extent without labels, margin ignored, ports before edges, ring without hole, 2 sub-scanlines, scale ignored, arrow reversed, catalogue entry removed, documentation row removed, decimal truncated, and the order test); Clippy and rustfmt clean; `cargo tree` shows no dependency without the feature. Limits: no text; strokes are joined by octagons and have no caps; a half-covered pixel of black on white is 127, by the fixed rounding; the whole corpus is rendered only by P7's board.
